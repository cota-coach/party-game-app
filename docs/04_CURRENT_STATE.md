# 1. プロダクト現在地

アプリ名：

**GROGGY GAMES / グロッキーゲーム**

BBQ、飲み会、家族・友人との集まりなどで、同じ場所にいる複数人がスマートフォン1台を使って遊ぶパーティーゲームWebアプリ。

コア思想：

- スマートフォンは参加者間で回さず、原則テーブル等に置いたまま使う
- アプリは司会、音声、効果音、ランダム処理、お題表示、ゲーム演出を担当する
- 成功判定、投票、多数派・少数派、最終敗者など、人間が簡単に判断できることは人間が判断する
- 初期MVPはオンライン対戦、ログイン、外部DB、有料API等を使わない
- 「高機能なシステム」より「実際の集まりで最後まで遊べること」を優先する

現在、初期2ゲームの主要機能とv0由来のデザイン移植まで完了し、`main` に統合済み。Vercelでスマートフォンから確認できる段階。

# 4. 実装済み：爆弾ゲーム

主要画面：

`app/bomb/page.tsx`

主要ロジック：

- `lib/bomb-game.ts`
- `lib/game-config.ts`
- `lib/audio.ts`
- `data/tongue-twisters.ts`

現在のフロー：

```text
遊び方
  ↓
ゲーム設定
  ↓
早口言葉決定
  ↓
開始者決定 / ルーレット
  ↓
GAME START
  ↓
PLAYING
  ↓
爆発
  ↓
再プレイ or HOME
```

基本ルール：

1. 柔らかいボールを1個用意する
2. 持っている人が画面の早口言葉を言う
3. 噛んだら最初から言い直す
4. 成功したら次の人へボールを渡す
5. 爆発音が鳴った瞬間の保持者が負け

早口言葉は1ラウンド中同じものを使う。成功判定は人間が行う。

## 爆発モード

- SHORT: 10〜40秒
- NORMAL: 20〜70秒
- LONG: 50〜120秒
- CHAOS: 10〜120秒

## 特殊指令

- リバース
- 1人飛ばし
- 2人飛ばし
- お前は2回じゃ！
- お前は3回じゃ！

抽選ウェイト：

- reverse: 25
- skipOne: 25
- skipTwo: 15
- repeatTwo: 20
- repeatThree: 15

イベント密度：

- 少なめ: 18〜30秒
- 普通: 12〜22秒
- 多め: 8〜15秒
- 鬼畜: 6〜11秒

同一指令の連続を原則避ける。有効指令が1種類だけなら再発を許可する。

## フェイク効果音

特殊指令とは別系統。

現在はON/OFF。ゲーム上の効果は持たない。

## 開始者

登録参加者が複数選択されている場合、開始者ルーレットを利用できる。

登録なしの場合は、その場の人間が開始者を決める。

# 5. 爆弾ゲームで絶対に守る設計

最重要：

**GAME START時に爆発予定時刻を1回だけ決定し、その後は変更しない。**

特殊指令、フェイク音、音声、UIアニメーション等を理由に爆発を遅らせない。

爆発は他イベントより優先する。

また、プレイヤーへ残り時間を推測させない。

禁止：

- countdown
- progress bar
- 残り秒数表示
- 爆発予定時刻表示
- 時間経過で短くなる導火線
- 残り時間に連動した色変更
- 残り時間に連動した波形速度
- 爆発直前だけ演出を激しくする等の時間リーク

現在の赤黒波形等は爆発残り時間と無関係な演出として扱う。

# 6. 爆弾ゲーム音声

`AudioManager` を `lib/audio.ts` に実装。

ゲーム開始時に背景音として ticking と timer を再生し、特殊指令中は背景音をduckする構成。

爆発時は他のゲーム音を停止し、爆発音を優先する。

主な音源：

```text
public/sounds/bomb/
  ticking/
    ticking.mp3
    timer.mp3
  explosion/
    explosion.mp3
    fail-trombone.mp3
  fake/
    fart-1.mp3
    fart-2.mp3
    fanfare.mp3
  roulette/
    drumroll.mp3
  commands/
    reverse.mp3
    skip-one.mp3
    skip-two.mp3
    repeat-two.mp3
    repeat-three.mp3
```

音源読み込み失敗によってゲームロジックをクラッシュさせない。

スマートフォンの自動再生制限を考慮し、ユーザー操作を起点にAudioを利用する。

### 実機確認事項

過去の開発中に「導火線音とtimer音が同時に鳴らない」問題が報告された経緯がある。

現在のコードは両方を背景音として開始する実装だが、この文書作成時点では実機で完全解消済みとは断定しない。今後の実機テストで再確認する。

# 7. 実装済み：究極の2択

主要画面：

`app/ultimate-choice/page.tsx`

データ：

`data/ultimate-choices.ts`

ロジック：

`lib/ultimate-choice.ts`

レベル：

- FAMILY
- ADULT
- HARD

複数選択可能。

基本進行：

1. 全員でA/Bを選ぶ
2. 多数派は抜ける
3. 少数派だけ残る
4. 残った人で次の問題
5. 最後は決定戦

アプリは以下を自動判定しない：

- 投票数
- 多数派
- 少数派
- 勝敗

人間がその場で判断する。

通常戦と決定戦は同じ `usedUltimateChoices` 履歴を共有する。

現在の本番コード内のお題はまだ動作確認用の仮データが中心。別の「お題開発・壁打ち」で採用コンテンツを確定し、後から本番データへまとめて投入する予定。

# 10. 今後のデザイン変更ルール

現在のゲーム機能と画面フローを土台として維持する。

軽微なデザイン変更はCodexで直接行ってよい。

例：

- 文字色
- サイズ
- 余白
- 背景装飾
- カード
- ボタン
- CSS animation
- モーション
- ローカル画像素材追加

デザイン変更時は、必要に応じて明示する：

**「ゲームロジック、音声、参加者管理、履歴、localStorage、画面遷移には変更を加えない。今回はビジュアルのみ変更する。」**

画像素材を追加する場合は、権利上問題のない画像を `public/images/` 等へ保存し、Codexに配置・レスポンシブ・演出を実装させる。

外部の一時的な画像URLへ恒久依存しない。

# 12. GitHub / Codex / Vercel 開発フロー

現在の基本フロー：

```text

        ↓
必要ならdocsへ確定仕様を保存
        ↓
Codexへ実装指示
        ↓
専用branch
        ↓
Codex実装・テスト
        ↓
Vercel Preview
        ↓
PC / スマートフォンで確認
        ↓
Pull Request
        ↓
mainへmerge
        ↓
Vercel Production
        ↓
実機最終確認
```

大きな変更は可能な限り専用branchで行い、Previewで確認してからmainへ入れる。

機能変更とデザイン変更は可能な限り分離する。
