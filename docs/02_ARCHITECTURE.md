# 1. 設計方針

本アプリは、

**「高機能なゲームシステム」ではなく、その場の人間同士の遊びをアプリが司会・演出する**

ことを基本思想とする。

そのため初期MVPでは、

-   過剰な自動化をしない
-   人間が簡単に判断できることは人間に任せる
-   DBやログインを導入しない
-   スマートフォン1台で成立させる
-   ゲームごとのロジックを分離する
-   後からゲームを追加できる
-   実際に遊んで調整しやすい
-   設定値をコード内に散らさない

ことを優先する。

------------------------------------------------------------------------

# 2. 全体アーキテクチャ

初期MVPは以下の構成とする。

``` text
GitHub
   │
   │ ソースコード管理
   ↓
Next.js Web App
   │
   │ GitHub連携
   ↓
Vercel
   │
   │ HTTPS公開
   ↓
スマートフォン
   │
   ├─ ブラウザから利用
   └─ ホーム画面から起動
```

初期MVPではサーバー側にゲーム状態を保存しない。

基本的なゲーム処理はすべてスマートフォンのブラウザ上で実行する。

------------------------------------------------------------------------

# 3. 技術スタック

## 3.1 フロントエンド

Next.jsを使用する。

基本構成：

-   Next.js
-   React
-   TypeScript
-   App Router

ゲームロジックは可能な限りClient Component側で処理する。

## 3.2 ホスティング

Vercelを使用する。

理由：

-   Next.jsとの相性が良い
-   GitHubと連携しやすい
-   更新・公開が簡単
-   初期MVP規模なら低コストで運用可能
-   スマートフォンからHTTPSで利用できる

基本フロー：

``` text
Codexで実装
↓
GitHubへ反映
↓
Vercelへ自動デプロイ
↓
スマートフォン実機確認
```

------------------------------------------------------------------------

# 4. 初期MVPでは使用しないもの

初期版では以下を導入しない。

-   外部データベース
-   独自バックエンドAPI
-   ユーザー認証
-   ログイン
-   WebSocket
-   オンラインマルチプレイ
-   有料AI API
-   音声認識API
-   外部TTS API
-   複雑な状態管理ライブラリ

必要になるまで追加しない。

# 6. ゲーム追加設計

各ゲームは可能な限り独立させる。

新しいゲームを追加する際、既存の爆弾ゲームや究極の2択のロジックを大きく変更しなくて済む構造を目指す。

共通処理だけを共有する。

共有候補：

-   参加者
-   localStorage
-   ランダム抽選
-   音声再生
-   共通ボタン
-   ダイアログ
-   HOMEのゲームカード

------------------------------------------------------------------------

# 7. データ保存

## 7.1 保存方式

初期MVPではブラウザの `localStorage` を使用する。

## 7.2 保存対象

最低限以下を保存する。

``` text
players
usedTongueTwisters
usedUltimateChoices
```

## 7.3 参加者

``` ts
type Player = {
  id: string;
  name: string;
};
```

## 7.4 ゲーム参加状態

登録参加者そのものと、今回のゲームに参加するメンバーは分離する。

ゲーム開始前に参加ON/OFFを選択する。この状態は基本的にゲームセッション用の一時状態として扱い、参加者名簿そのものを変更しない。

## 7.5 登録なしでの開始

`players` が空でもゲーム開始を禁止しない。

-   参加者あり → 爆弾ゲームの開始者ルーレットを使用可能
-   参加者なし → その場で開始者を決めてSTART
-   究極の2択 → 参加者登録なしでもそのまま開始可能

------------------------------------------------------------------------

# 8. 出題履歴

## 8.1 早口言葉

使用済みIDを `usedTongueTwisters` に保存する。

## 8.2 究極の2択

使用済みIDを `usedUltimateChoices` に保存する。

## 8.3 履歴の維持

ゲームからHOMEへ戻っても履歴を削除しない。

## 8.4 履歴リセット

HOMEから明示的に「出題履歴をリセット」を実行した場合のみ、

-   `usedTongueTwisters`
-   `usedUltimateChoices`

を削除する。

`players` は削除しない。

------------------------------------------------------------------------

# 9. 早口言葉データ

データとゲームロジックを分離する。

``` ts
type TongueTwister = {
  id: string;
  text: string;
  difficulty: "easy" | "normal" | "hard";
};
```

ゲーム側は条件に合う未使用問題を抽選する。

------------------------------------------------------------------------

# 10. 究極の2択データ

``` ts
type UltimateChoice = {
  id: string;
  optionA: string;
  optionB: string;
  categories: string[];
  level: "family" | "adult" | "hard";
};
```

カテゴリは複数指定可能。初期MVPではカテゴリによる画面フィルターは必須ではない。

------------------------------------------------------------------------

# 11. ランダム抽選

ランダム処理は `lib/random.ts` 等に共通化する。

用途：

-   早口言葉抽選
-   究極の2択抽選
-   爆発時間
-   特殊指令
-   特殊指令発生間隔
-   フェイク効果音
-   フェイク効果音発生間隔
-   開始者ルーレット

------------------------------------------------------------------------

# 12. 爆弾ゲーム全体構造

基本状態：

``` text
SETUP
↓
ROULETTE / READY
↓
PLAYING
↓
EXPLODED
```

------------------------------------------------------------------------

# 13. 爆弾ゲーム設定

ゲーム開始前に以下を設定する。

-   参加者：登録済み参加者のON/OFF。登録なしでも開始可能
-   早口言葉難易度：おまかせ / EASY / NORMAL / HARD
-   爆発時間：SHORT / NORMAL / LONG / CHAOS
-   特殊指令：5種類を個別ON/OFF
-   イベント量：少なめ / 普通 / 多め / 鬼畜
-   フェイク効果音：ON / OFF

初期MVPではフェイク音の個別選択は必須としない。

------------------------------------------------------------------------

# 14. 爆発タイマー設計

爆弾ゲームで最も重要なロジック。

STARTした瞬間に、**絶対的な爆発予定時刻を1回だけ決める。**

``` ts
const startedAt = Date.now();
const duration = randomBetween(minSeconds, maxSeconds) * 1000;
const explosionAt = startedAt + duration;
```

以降 `explosionAt` を変更しない。

## 14.1 爆発時間設定

``` ts
const EXPLOSION_RANGES = {
  short: { min: 10, max: 40 },
  normal: { min: 20, max: 70 },
  long: { min: 50, max: 120 },
  chaos: { min: 10, max: 120 }
};
```

実地テスト後に数値だけ変更できるようにする。

## 14.2 爆発優先順位

爆発はすべてのイベントより優先する。

以下の途中でも爆発する。

-   特殊指令再生中
-   フェイク効果音直後
-   2回じゃ実行中
-   3回じゃ実行中
-   ticking中

イベント都合で爆発予定時刻を延長しない。

------------------------------------------------------------------------

# 15. ticking設計

PLAYING開始と同時に再生し、EXPLODEDになったら停止する。

初期MVPでは一定テンポでよい。残り時間に応じたテンポ変更は行わない。

------------------------------------------------------------------------

# 16. 特殊指令スケジューラ

特殊指令は爆発タイマーとは別系統で動かす。イベント数は固定しない。

------------------------------------------------------------------------

# 17. 特殊指令発生間隔

初期設定：

``` ts
const EVENT_INTERVALS = {
  low: { min: 18, max: 30 },
  normal: { min: 12, max: 22 },
  high: { min: 8, max: 15 },
  brutal: { min: 6, max: 11 }
};
```

各イベント後に次の発生時間を再抽選する。

------------------------------------------------------------------------

# 18. 特殊指令抽選確率

初期設定：

``` ts
const COMMAND_WEIGHTS = {
  reverse: 25,
  skipOne: 25,
  skipTwo: 15,
  repeatTwo: 20,
  repeatThree: 15
};
```

OFFになっている指令は候補から除外し、残った指令だけで重み付き抽選する。

同じ特殊指令を2回連続で発生させない。ただし候補が1種類しかONになっていない場合は再発を許可する。

------------------------------------------------------------------------

# 19. 特殊指令保護時間

特殊指令が重なりすぎないようにする。

特に `repeatTwo` と `repeatThree`
は参加者の実行時間が必要なため、特殊指令発生後に保護時間を設けられる構造とする。

具体的な秒数は `game-config.ts`
等にまとめ、実地テスト後に変更可能とする。

**保護時間は爆発タイマーには影響しない。**

------------------------------------------------------------------------

# 20. フェイク効果音スケジューラ

フェイク効果音は特殊指令とは別系統で管理する。

``` text
ゲームSTART
│
├─ 💥 爆発タイマー
├─ 🎭 特殊指令スケジューラ
└─ 😂 フェイク効果音スケジューラ
```

フェイク効果音にはゲーム上の効果を持たせない。

候補：

-   リアルなおなら
-   不発風の音
-   パフパフ
-   電話ベル
-   動物音
-   サイレン
-   その他のおふざけ効果音

## 20.1 音声衝突対策

特殊指令とフェイク音が完全に同時再生され、指令が聞き取れなくなることは避ける。

重要な特殊指令音声を優先する。ただし爆発だけは例外で、爆発時刻になった場合は他の音声状態に関係なく爆発処理へ移行する。

------------------------------------------------------------------------

# 21. 爆発処理

爆発時：

1.  ゲーム状態をEXPLODEDへ変更
2.  特殊指令タイマー停止
3.  フェイク効果音タイマー停止
4.  ticking停止
5.  不要な音声停止
6.  爆発音再生
7.  爆発演出表示

敗者の名前はアプリで自動判定しない。

------------------------------------------------------------------------

# 22. 音源設計

音源は `public/sounds/` 配下で管理する。

基本形式はMP3。

固定音声は原則として **1イベント = 1音声ファイル** とする。

例：

``` text
reverse.mp3
skip-one.mp3
skip-two.mp3
repeat-two.mp3
repeat-three.mp3
explosion.mp3
```

録音自体は1本の長い音声で行い、後から分割してもよい。

------------------------------------------------------------------------

# 23. 音声再生共通処理

音声再生処理は `lib/audio.ts` 等へまとめる。

必要な処理：

-   再生
-   停止
-   ループ
-   ticking停止
-   現在再生中音声管理
-   爆発時の強制停止
-   音声競合防止

------------------------------------------------------------------------

# 24. スマートフォンの音声制限対策

モバイルブラウザではユーザー操作なしの音声再生が制限される場合がある。

そのため、**「ゲームSTART」ボタンのユーザー操作を起点として音声再生を開始できる構造**とする。

実機テスト必須項目とする。

------------------------------------------------------------------------

# 25. 究極の2択ゲーム状態

基本状態：

``` text
SETUP
↓
QUESTION
↓
QUESTION
↓
FINAL
↓
FINISHED
```

勝敗はアプリが判定しない。

------------------------------------------------------------------------

# 26. 究極の2択設定

開始前に以下を複数選択可能とする。

-   FAMILY
-   ADULT
-   HARD

最低1つは選択されている状態で開始する。

------------------------------------------------------------------------

# 27. 究極の2択抽選

``` text
選択されたレベル
↓
該当する全問題
↓
使用済みIDを除外
↓
ランダム抽選
↓
表示
↓
使用済みIDへ追加
```

通常問題と決定戦は同じ使用済み履歴を共有する。

------------------------------------------------------------------------

# 28. 究極の2択画面

問題画面ではA/Bを大きく表示する。

画面下部に最低限、

-   次の究極の2択
-   決定戦に行く

を配置する。

自動進行しない。

------------------------------------------------------------------------

# 29. 決定戦

「決定戦に行く」を押すとFINAL状態へ移行し、新しい未使用問題を抽選する。

決着しなかった場合は「もう一度、決定戦」で新しい問題を出す。

勝敗判定は人間が行う。

------------------------------------------------------------------------

# 30. 究極の2択の音声

初期MVPでは自動読み上げを実装必須としない。

問題データと表示処理は分離し、後から `speechSynthesis`
等を追加できる構造にする。

将来的には、

-   固定録音司会
-   Web Speech API
-   人間による手読み

を組み合わせられる。

------------------------------------------------------------------------

# 31. 「遊び方」画面

各ゲームに独立した遊び方画面を用意する。

目的は **30秒程度でルールが理解できること**。

## 31.1 爆弾ゲーム

最低限説明する内容：

-   実物の柔らかいボールを使う
-   スマホは置いたまま
-   早口言葉を成功したら渡す
-   噛んだらやり直し
-   爆発時の保持者が負け
-   特殊指令5種類
-   フェイク効果音はルールに影響しない

## 31.2 究極の2択

最低限説明する内容：

-   全員A/Bを選ぶ
-   多数派が抜ける
-   少数派が残る
-   少数派で繰り返す
-   最後は決定戦
-   アプリは投票を管理しない

------------------------------------------------------------------------

# 32. HOME設計

HOMEはアプリ全体の入口。

最低限：

``` text
PARTY GAME

[ 💣 爆弾ゲーム ]

[ 😈 究極の2択 ]

----------------

参加者管理

出題履歴をリセット
```

ゲーム追加時はゲームカードを追加できる構造とする。

------------------------------------------------------------------------

# 33. 参加者管理

参加者管理では、

-   追加
-   編集
-   個別削除
-   全員削除

を行う。

削除系には確認ダイアログを使用する。

全員削除と出題履歴リセットを混同させない。

------------------------------------------------------------------------

# 34. UI基本設計

スマートフォン縦画面を最優先する。

目標：

-   片手でも操作可能
-   大きなタップ領域
-   誤操作しにくい
-   屋外でも読める
-   酔っていても分かる
-   説明を読まなくても主要操作が分かる

ゲーム中は設定項目を極力表示しない。

爆弾ゲームでは残り時間を表示しない。

------------------------------------------------------------------------

# 35. PWA方針

将来的にはPWAとして強化する。

目標：

-   ホーム画面追加
-   アプリアイコン
-   standalone表示
-   基本画面のキャッシュ
-   ゲームデータのキャッシュ
-   固定音源のキャッシュ
-   オフライン利用

ただし初回実戦版では、**ゲームが安定して動くことをPWA完成より優先する。**

Service Worker等の本格的なオフライン対応はv0.2以降でもよい。

------------------------------------------------------------------------

# 36. 設定値の一元管理

実地テストで変更しそうな値はゲームロジックへ直接埋め込まない。

`lib/game-config.ts` 等にまとめる。

対象：

-   爆発時間
-   特殊指令間隔
-   特殊指令確率
-   特殊指令保護時間
-   フェイク音間隔
-   その他タイミング

目的は、**実際に遊んだ後に数字だけ簡単に変更できること**。

------------------------------------------------------------------------

# 37. タイマー管理

爆弾ゲームでは最低限、

-   explosion timer
-   command timer
-   fake sound timer

を管理する。

コンポーネントのアンマウント時、ゲーム終了時、HOMEへ戻る時には、不要な
`setTimeout`、`setInterval`、Audioを確実に停止・破棄する。

ゲーム終了後に突然音が鳴る状態を防ぐ。

------------------------------------------------------------------------

# 38. エラー・例外処理

## 38.1 参加者0人

ゲーム開始可能。

## 38.2 参加者1人

ゲーム開始を禁止する必要はないが、ルーレットの意味が薄いため適切に表示する。

## 38.3 特殊指令全部OFF

特殊指令スケジューラを動かさない。爆弾ゲーム自体は正常に進行する。

## 38.4 フェイク効果音OFF

フェイク音スケジューラを動かさない。

## 38.5 音源読み込み失敗

ゲーム全体をクラッシュさせない。爆発処理そのものは継続する。

## 38.6 localStorage異常

保存データが存在しない場合は空データとして初期化する。JSON解析に失敗してもアプリ全体をクラッシュさせない。

------------------------------------------------------------------------

# 39. お題枯渇時

未使用問題が0件になった場合、自動で履歴をリセットして黙って再出題することは避ける。

「この条件のお題を全部使いました」と表示し、

-   HOMEで履歴をリセットする
-   条件を変更する

等を選べるようにする。
